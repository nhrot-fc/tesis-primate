\section{Alcance}

\rotulo{Medio de verificación.} Scripts de \file{src/}, \file{pyproject.toml} y este manual
técnico; curvas y costos generados por \file{RE\_2-2\_\allowbreak pipeline.ipynb} sobre las
corridas de \file{runs/}.

\rotulo{Contenido.} El \emph{pipeline} completo, de las tablas de Raven a las tablas de
Raven: instalación, comando de cada etapa, archivo que produce y cómo se reproduce. RE1.1,
RE1.2 y RE2.1 documentan el porqué de cada decisión.

\rotulo{Indicador.} El pipeline genera las particiones procesadas (sección~\ref{sec:datos}),
entrena desde una configuración (sección~\ref{sec:entrenamiento}), evalúa un
\emph{checkpoint} (sección~\ref{sec:evaluacion}) y ejecuta inferencia sobre un WAV
(sección~\ref{sec:inferencia}), con dependencias y comandos declarados.

\section{Instalación}

El proyecto se gestiona con \code{uv}; \file{pyproject.toml} declara Python
$\geq$~\pythonVersion{}, las dependencias base (PyTorch \torchVersion{}, torchvision,
torchaudio, pandas, soundfile, PyQt6) y dos extras: \code{detr} (transformers, timm) para las
dos arquitecturas DETR y \code{yolo} (ultralytics, opencv) para YOLO. Los grupos
\code{train} y \code{notebooks} añaden lo que hace falta para preparar datos, entrenar,
comparar y ejecutar los cuadernos.

\begin{lstlisting}[language=bash]
git clone https://github.com/nhrot-fc/tesis-primate.git && cd tesis-primate
uv sync --all-extras --all-groups        # investigación: todo
uv sync --no-dev --extra detr --extra yolo   # sólo inferencia con cualquier checkpoint
\end{lstlisting}

Los pesos preentrenados (AST de AudioSet, Deformable DETR de COCO) se descargan de Hugging
Face la primera vez y quedan en \file{hf/}; los de torchvision y Ultralytics, en sus cachés
habituales. Hardware de referencia: una GPU de 24\,GB para entrenar (lote 8 del DETR ocupa
$\approx$16\,GB); la inferencia corre en CPU. \todocita{PyTorch (Paszke et al. 2019),
Hugging Face Transformers (Wolf et al. 2020) y Ultralytics, si el jurado pide citar el
software}

\section{Datos: \file{prepare\_annotations.py} y \file{prepare\_data.py}}
\label{sec:datos}

\begin{lstlisting}[language=bash]
uv run python src/prepare_annotations.py [--force]   # RE1.1: raw/ -> cleaned/
uv run python src/prepare_data.py [--force]          # RE1.2: cleaned/ -> processed/
uv run python src/export_yolo.py                     # sólo para YOLO: processed/ -> yolo/
\end{lstlisting}

Ambos scripts se niegan a sobrescribir salvo con \code{--force}, escriben un registro con lo
que descartaron y son deterministas (semilla en \file{meta.json}). El export de YOLO pinta cada
ventana como PNG en gris de $512 \times 512$ con las cajas en el formato de Ultralytics, y
guarda una copia de \file{meta.json} para negarse a entrenar sobre un export de otra versión del
caché.

\section{Entrenamiento: \file{train.py}}
\label{sec:entrenamiento}

\subsection{Interfaz}

\begin{lstlisting}[language=bash]
uv run python src/train.py --arch detr        --name detr_t10_logmel --hp frontend=logmel --device cuda:2
uv run python src/train.py --arch detr_resnet --name detr_resnet
uv run python src/train.py --arch frcnn       --name frcnn_v2
uv run python src/train.py --arch yolo        --name yolo26s_v2 --hp model=yolo26s
uv run python src/train.py --arch detr --limit 64 --cfg epochs=1 workers=0   # prueba de humo
# preentrenar la cabeza con aves y afinar con primates (RE2.1); envuelve a train.py sin tocar src/
uv run python notebooks/pretrain_birds_train.py --name detr_birds --device cuda:2
uv run python notebooks/pretrain_birds_train.py --finetune runs_extra/detr_birds/best.pt --name detr_t10_logmel_birds
\end{lstlisting}

\code{--arch} elige un preset (RE2.1, Tabla de recetas): la arquitectura del registro
\code{models.registry.ARCHITECTURES} más sus hiperparámetros y su \code{TrainConfig}.
\code{--hp clave=valor} pisa un hiperparámetro del modelo y \code{--cfg clave=valor} uno del
entrenamiento (épocas, lote, tasa de aprendizaje, \textit{workers}); \code{--limit} recorta
el conjunto para una prueba de humo. Todo lo que se pisa queda escrito en el nombre de la
corrida si no se da \code{--name}, y siempre en \file{config.json} y en el
\emph{checkpoint}. \file{notebooks/pretrain\_birds\_train.py} llama a \code{train.main()}
con el caché de aves (\file{data/processed\_extra/}) y la carpeta \file{runs\_extra/}, y
para afinar carga en el modelo recién construido todo tensor del preentrenado con el mismo
nombre y forma (queda fuera lo que depende del número de clases); la corrida resultante es una
más de \file{runs/}.

Un \emph{checkpoint} es autocontenido: \code{models.registry.load\_checkpoint(path)}
reconstruye el modelo a partir de \code{architecture}, \code{hparams} y el número de clases
de \code{labels}, carga el \code{state\_dict} en modo estricto (ninguna clave puede faltar ni
sobrar) y devuelve el modelo junto con las etiquetas, la configuración y el umbral de
operación si existe. Es lo que abren \file{detect.py}, el visor y \file{dump\_predictions.py}.

\section{Evaluación: \file{dump\_predictions.py} y \file{compare\_models.py}}
\label{sec:evaluacion}

\begin{lstlisting}[language=bash]
uv run python src/dump_predictions.py --run detr_t10_logmel_v2 --device cuda:1
uv run python src/compare_models.py runs/*/*_predictions.pt --output runs/comparacion/comparacion_modelos
DEVICE=cuda:1 ./evaluation.sh [nombres...]     # las dos cosas, para las corridas con best.pt
\end{lstlisting}

El volcado guarda, por ventana de validación y de prueba, todas las cajas con confianza
$\geq 0{,}001$ junto con las cajas anotadas y el mapa ventana $\to$ grabación; la comparación
aplica el protocolo de RE2.1 sobre esos volcados y escribe un \file{.txt} legible, un
\file{.json} con las mismas cifras y, en cada corrida, \file{operating\_point.json}.
\file{evaluation.sh} encadena ambas cosas y vuelca solo lo que esté desactualizado respecto de
su \file{best.pt}. Cambiar una métrica o un umbral no exige volver a pasar los modelos por
la GPU.

\section{Inferencia: \file{detect.py} y el visor}
\label{sec:inferencia}

\begin{lstlisting}[language=bash]
uv run python src/detect.py grabaciones/ otra.wav --model runs/yolo26s_v2/best.pt [--score 0.10]
uv run python src/main.py [audio.wav | carpeta/]                 # visor (Spectrogram | Batch)
\end{lstlisting}

\file{detect.py} recorre archivos o carpetas, corta cada grabación en las mismas ventanas de
3\,s con salto de 1,5\,s del caché, ejecuta el modelo por lotes, funde los duplicados entre
ventanas solapadas y escribe junto a cada audio una tabla de selección de Raven con las cajas
por encima del umbral (por defecto, el punto de operación del modelo). RE2.4 documenta el
formato de salida y la demostración; el visor y el paquete portable para Windows
(\file{deploy/build\_windows.py}, que empaqueta un Python embebido con los lanzadores
\file{Detector.exe} y \file{detect.exe}) se describen en RE2.5.

\section{Reproducibilidad}

\begin{itemize}
    \item \textbf{Semillas.} Una semilla única (42) fija la partición, las ventanas vacías, el
          orden de los lotes y las aumentaciones; YOLO recibe la misma y corre en modo
          determinista.
    \item \textbf{Trazabilidad.} Cada \emph{checkpoint} lleva el \file{meta.json} del caché
          con el que se entrenó y sus hiperparámetros; cada corrida, su \file{config.json} y su
          registro con marcas de tiempo. Las cifras de este documento salen del cuaderno homónimo
          sobre esos archivos; \emph{commit} \code{\commit}.
    \item \textbf{Fallo temprano.} \code{prepare\_*} se niegan a pisar salidas,
          \code{train.py --arch yolo} se niega a entrenar sobre un export de otra versión del
          caché, \code{compare\_models.py} se niega a comparar volcados que no evaluaron las
          mismas ventanas, y \code{load\_checkpoint} carga en modo estricto.
    \item \textbf{Pruebas de humo.} \code{--limit N --cfg epochs=1 workers=0} recorre el ciclo
          completo en minutos; es la prueba que precede a cada corrida larga.
    \item \textbf{Lo que no está fijado.} El orden de las operaciones en GPU no es determinista
          en todos los núcleos de cuDNN: dos corridas con la misma semilla dan curvas parecidas,
          no idénticas. El costo de una corrida depende de la carga de la GPU compartida.
\end{itemize}

\todocita{reproducibilidad en aprendizaje automático (Pineau et al. 2021, \emph{Improving
reproducibility in machine learning research}) para encuadrar esta lista}
