# Contributing to This Project

Thank you for your interest in contributing to this academic paper project!

## How to Contribute

### Reporting Issues

If you find any issues with the LaTeX compilation or document structure:
1. Check if the issue already exists in the Issues section
2. Create a new issue with a clear description
3. Include any error messages or compilation logs

### Suggesting Improvements

Suggestions for improving the template or document structure are welcome:
1. Open an issue describing your suggestion
2. Explain the benefits of the proposed change
3. Provide examples if applicable

### Making Changes

If you'd like to contribute directly:

1. Fork the repository
2. Create a new branch for your changes
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. Make your changes
4. Test compilation
   ```bash
   make clean
   make
   ```
5. Commit your changes with a clear message
   ```bash
   git commit -m "Description of your changes"
   ```
6. Push to your fork and submit a pull request

## Style Guidelines

### LaTeX Code

- Use consistent indentation (2 or 4 spaces)
- Add comments to explain complex LaTeX code
- Keep lines under 100 characters when possible
- Use semantic markup (e.g., `\emph{}` instead of `\textit{}`)

### Bibliography

- Follow a consistent citation style
- Include all required fields for each entry type
- Use meaningful citation keys (e.g., `author2024title`)

### Commit Messages

- Use clear, descriptive commit messages
- Start with a verb (e.g., "Add", "Fix", "Update", "Remove")
- Keep the first line under 50 characters
- Add details in the body if needed

## Questions?

If you have questions about contributing, feel free to open an issue with the "question" label.
